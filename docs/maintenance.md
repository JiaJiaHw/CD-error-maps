# 后续维护与本地清理

当前固定样本实验已经完成。后续遇到问题或需要扩展时，先阅读本地任务进度、已有配置和完成记录，确认受影响的输入、代码及运行范围，避免重复选样或覆盖已验收产物。

## 保留可复查的实验

- 保留原始 `selection.json`、`selection.sha256`、`EXPORT_COMPLETE.json`、各数据集 `samples.csv`/`test.txt` 及完整 T1/T2/GT；冻结后不改写 ID、顺序、名称或内容。
- 保留完整 Prediction、显式映射及上游来源记录，本地配置中的编码、GT 映射和冻结哈希也属于实验依据。
- 保留每个已验收运行的完整目录，包括 RGB/类别索引、图例、统计、配对、配置、报告、哈希及 `COMPLETE.json`，不只保留可视化 PNG。
- 保留任务进度、导入/来源/独立回读证据，以及环境定义和已验证的项目环境；这些不是临时文件。

`verify` 会重读运行报告中记录位置的原始 GT/Prediction。移动或删除输入会影响旧运行验收。需要迁移时保留完整备份及原路径记录，旧运行仍按记录的位置检查；新位置使用新配置、新运行，不修改旧封印来“修复”路径。

## 修改代码或更换输入

1. 检查 Git 状态和现有提交，保存与新需求相关的改动，不覆盖其他人的工作。
2. 已有 `.conda` 环境可直接激活；只有依赖发生必要变化时再调整项目环境，不修改模型环境。
3. 根据改动范围执行必要测试。文档整理检查链接、命令和配置描述即可；编码、配对或产物变化需相应合成测试。不要为文档收尾重新生成真实结果。
4. 新输入先 `validate`，必要时生成少量预览并核对，然后在未占用的新目录中 `generate` 和 `verify`。已有结果保持原样。
5. 更新公开功能说明和本地任务记录，提交前检查 diff、暂存范围、忽略规则与真实数据边界。

公开仓库保存通用代码、测试、文档、模板、环境/CI 定义和 `.gitkeep`。个人路径、原始清单、真实图片、Prediction、结果、个人配置、环境实际文件和本地证据保持忽略。

## 清理可以重新产生的文件

确认没有引用且不属于实验证据后，可清理 `__pycache__`、测试缓存、打包生成的 `build/`/`*.egg-info/`、明确失败或已替代的合成 fixture、导入暂存目录和冗余开发副本。

清理前列出精确路径、用途和待保留文件；有不确定性时保留。不要仅凭名称包含 `tmp`、`old`、`test` 或 `output` 批量删除，不要把全部历史记录或真实运行当作缓存。对项目外的源数据、模型权重、完整 test 结果和服务器目录另行确认，不扩展清理范围。
